MAJOR CONCERNS

1. **Fig. 3 (latency.pdf) is again stale relative to the data — it marks a completed run "not run."** `make_figures.py` line 84 still maps the Q3.8 thinking-on measured cell to `None`, so the rendered figure prints "not run" for `qwen3.8-27b-onm-s` — a run that now exists and whose results Sec. V-C reports (49.9 s, 157.9 s). The same block also omits `qwen3-30b-onm-s`: the only thinking-on measured bar shown is the concurrent 103.1 s upper bound, while the caption now tells readers "the serial thinking-on arm ... gives the deployed latency" — an arm the figure does not display. Text and figure flatly disagree. Fix `LAT_CELLS` to include both `-onm-s` cells (serial, n=50), regenerate, and reconcile the caption.

2. **Limitations and Table II contradict the new Sec. V-C results.** (a) Line 215 still reads "The measured thinking-on result comes from one model on 50 encounters under concurrent execution, and no informative serial thinking-on measurement exists." That sentence is now false twice over — two informative serial thinking-on measurements exist and are reported in the same paper. (b) Table II's measured-latency block omits both new serial rows although Sec. III-E promises the table covers "every arm we report": add Qwen3-30B plans/on/serial/16.5 s -> 55.3+-8.7 (92%, n=50) and Qwen3.8-27B plans/on/serial/49.9 s -> 157.9+-23.2 (94%, n=50, 98% success). These are one-line fixes but are internal contradictions a second reader will find immediately.

3. **The qwen3.8 "serial" run's metadata does not support strictly serial execution.** `qwen3.8-27b-onm-s/meta.json` reports `wall_s = 1530 s`, but 50 serial calls at the reported 49.9 s mean charged latency require >= ~2495 s. For comparison, `qwen3-30b-onm-s` (839 s wall vs ~825 s summed latency) is consistent with serial execution. The likeliest explanations — resume from a partial-run cache (cached calls retain their original latency but cost no wall time) or >1 episode worker — have different consequences: resume is benign if the earlier session was serial and uncontended; a second worker on a single-sequence server would mean the 49.9 s includes queueing and the "serial/deployed" label is wrong (the true serial value could be roughly half). This needs an explanation, and if the cache was resumed, confirmation that the inherited latencies were measured under the same uncontended serial conditions. The conclusion (latency >> break-even) survives either way, but the number's provenance is currently unverifiable.

4. **Sec. V-D's significance claim is inconsistent with its own numbers.** Line 165 states "only qwen3.8's interval excludes zero," but the reported vl-12b paired difference is -5.1+-4.0 s, i.e., [-9.1, -1.1], which also excludes zero; "p~=0.1 for the other three" is likewise incompatible with a 95% interval that excludes zero. Either the vl-12b interval is misprinted or the sentence is wrong. If vl-12b's interval truly excludes zero, the claim should be that the image-only advantage is established for two of four models — which strengthens, not weakens, the modality finding.

5. **The "fair random tiebreak" claim lacks a disclosed caveat the authors already found.** The text reports the A-win split (60% plain, 55% commit) but the fact that the plain draw produces only 92 distinct card pairs over 200 encounters — because the key is `ids|detection_time` and detection times collide — appears only in a LaTeX source comment (`% VERIFIED ... only 92 distinct pairs`), invisible to readers. Consequences the paper should state plainly: card outcomes are correlated across encounters sharing a key, so the draw is not an independent per-encounter coin; and 120/200 is a ~2.8-sigma deviation from even (over only ~92 effective keys). The commit variant improves the keying but still yields 100 distinct pairs (episode seed shared across the two layouts). Either soften "fair" throughout (abstract, contribution 5, Sec. V-F) to what is demonstrated — unpredictable-by-construction and unsteerable under non-adversarial broadcast — or report the split over distinct keys. The operational claim ("resolves every conflict; worse fallback than the rulebook") is unaffected.
