# Gazebo round 2: convoy, T-junction and lossy comms vs the 2D sim

Gazebo Harmonic + ROS 2 Jazzy, 3× TurtleBot3 Waffle (2 for comms), one run per scenario × policy × seed. Per-run outcomes: `data/tables/gazebo/gazebo_r2_runs.csv`.
Scenarios are generated by `python experiments/gazebo/make_scen_r2.py` (6 seeds per kind; start delays of the
non-leading robots jittered per seed) and run with `experiments/gazebo/run_one.sh` over `runs_r2.txt`.
Kinds: `convoy` (2-robot convoy vs 1 oncoming, `corridor_convoy.yaml`), `tj` (robot leaves the stem,
`corridor_tjunction.yaml`), `tjgoal` (robot turns into the stem, `corridor_tjunction_goal.yaml`) and `comms`
(single bay, 0.5 s latency ± 0.2 s, 50% loss). Policies: fixed priority, default rulebook, `cost_bid`.
The 2D comparison runs the same scenario files and seeds in `sim2d`.

## What Gazebo exposed

1. **Unreachable goal (scenario bug).** In `corridor_tjunction.yaml` robot S's goal was x = −2.5, which is the
   west wall of the end room. The 2D sim does not put walls in perception, so S drove into the wall (41 wall
   hits) and "arrived"; in Gazebo the lidar sees the wall, S stops 7 cm short and never finishes, so every `tj`
   run timed out as a deadlock. Fixed: goal −1.5, plus `test_scenario_goals_reachable_without_touching_room_walls`.
   2D T-junction study (18 runs/policy) before → after the goal fix: reactive 8 → 14/18 successes; mean delay
   fixed priority 90 → 89.6 s, rulebook 105 → 85.6 s, `cost_bid` 72 → 72.3 s (all negotiating policies 18/18).
2. **Lidar occlusion in the deep stem (sim-to-real gap).** In `tjgoal`, S waits in the 2 m-deep stem until the
   corridor is clear (`Agent.lane_clear`). That check used sensed peers only; in Gazebo the stem walls hide the
   corridor, so S left while B was still approaching and B had to reverse into the far room (+52 s makespan,
   a different first yielder). The 2D sim has no occlusion. Fix: `lane_clear` also counts peers whose fresh
   STATE message says they are moving towards the refuge (`Agent.known_peer_positions`). In 2D the 72
   round-2 cases are unchanged except `tj` seed 0 under fixed priority / rulebook (+4 s).
3. **Collision after the reactive fallback.** `tjgoal` seed 0, fixed priority: with no feasible plan
   (`lower_id_priority:infeasible`) both robots fell back to reactive back-off; B swung forward into bay0 while A
   had stopped beside the bay mouth, and B's body clipped A (centre distance 0.21 m). The same case deadlocks
   in 2D on `main` and succeeds in 2D with PR #13.

## Limits

- 6 seeds per cell; one Gazebo run per case. Makespan differences are means over runs that succeeded in both.
- The stem is still a deep-bay approximation of a T-junction.
- The 2D sim still has no lidar occlusion; the STATE fusion makes the decision robust to it, but other
  sensor-only checks (e.g. `bay_seen_occupied`) could differ in Gazebo.
- Shutdown tracebacks (`Unable to convert call argument '0'`) in ROS 2 subscription cleanup appear after some
  completed runs; they do not affect referee outcomes.
